This is a dataframe with transects conducted in an area of 70.9 sqkm, over 7 replicates. Sample label is the unique ID given to each line in the area. Each individual line length is given in the Effort.s column. Effort is then multiplied by number of replicates. The distance column has all the associated perpendicular distances (in meters) to the sightings. If a line has multiple individuals, each is represented by a separate row. Remember you also need the lines without any detections, do not eliminate those!

You can fit a detection function with just a column of distances. However, to have density and abundance estimates, you need columns for transect length (effort) and area for the study region.

Very important to tell distance your units of measurements or estimates can go wrong! Arguements for the convert_units function are as follows:

  • distance_units: units of measure for perpendicular/radial distances
  • effort_units: units of measure for effort (NULL for point transects)
  • area_units: units of measure for the study area.
conversion.factor <- convert_units(distance_units = "meter", effort_units = "kilometer", area_units = "square kilometer")

Fit half-normal detection function

Details about the arguments for this function: + key="hn": half-normal (this is default) + (key="hr"): hazard-rate + (key="unif"): uniform (rarely used)

The different options available for adjustment terms are:

  • adjustment=NULL: do not include adjustment terms

+(adjustment="cos"): cosine adjustment term (this is default) +(adjustment="herm"): Hermite polynomial +(adjustment="poly"): Simple polynomial + convert.units=conversion.factor- this argument is extremely important since data are not always measured in the same units. In this dataset, the perpendicular distances are measured in meters and the line transect lengths are in kilometer; this argument converts the perpendicular distance measurements from meters to kilometer.

The summary gives information on the model that has been fit along with density and abundance estimates. Page wise

  • number of detections used in fitting the model
  • truncation distance
  • AIC score
  • parameters of the detection function (on a natural log scale)
  • estimated probability of detection (Pa)
  • estimated number of objects in the area covered by survey effort
  • summary of the survey (effort, number of transects, number of detections)
  • encounter rate and its variability
  • estimated abundance and density within the study area and measures of precision
  • if data have regional strata (or any other type of stratification), estimates are provided for each stratum
  • if objects were detected in groups, there are estimates of abundance of groups and of individuals

One thing to note, encounter rates are simply groups/individuals that were present. This is not densities. So poor visibility or poor encounter rates do not necessarily mean low densities. Similarly high sightings and large number of detections do not mean higher animal densities.

Check the goodness of fit for this model. The function used by default reports the goodness of fit assessed by the Cramer von-Mises (CvM) test along with a quantile-quantile plot showing locations of deviations from good fit. You can perform a goodness of fit test and a bootstrap version of the Kolomogorov-Smirnov goodness of fit test if needed. By default gof_ds conducts a CvM test.

Truncation; for distance sampling, we ignore a small number of very distant detections — this is called truncation. The far-away sightings are rare and noisy, and don’t contribute much towards detectability close to the transect, which is the part of the curve we rely on most. Keeping these distances can pull the detection function into strange shapes and inflate uncertainty. Truncating the furthest few percent of detections, helps us better estimate how many animals we missed overall.

Remember truncation doesnt mean these animals dont exist, they are eventually accounted for by the detection function.Best practice is to run the data without truncation and see what the curve looks like. Ideally truncate the furthest 5 percent of detections for line transects, and sometimes up to 10 percent for point transects. Test what changes with a 5% truncation vs a 10%

DO NOT use AIC to compare truncated data with untruncated or truncations of different values with each other. AIC cannot be used if

  • sample size n differs
  • truncation distance w differs
  • data are grouped, and cut points differ
  • data are grouped in one analysis and ungrouped in the other

A note on model Coefficient of Variation (CV) and Confidence Intervals (CI). CV measures relative uncertainty. Gives information on how precise the estimate is, not whether it is correct or not. A general rule of thumb (for intuition):

  • CV < 20% → high precision

  • 20–30% → moderate precision

  • 30% → low precision (be careful using these estimates)

Ultimately two estimates can have the same density but very different CVs — the one with lower CV is more reliable.

A confidence interval shows the range of values for the true density. A wide CI means more uncertainty, even if the point estimate looks reasonable. Narrow CIs mean the data strongly constrain the estimate.

Point estimates tell you what the density might be; CV and CI tell you how much confidence you should place in it.
